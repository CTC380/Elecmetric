    Questions

    What is two’s complement?

    Two’s complement is the way almost every computer stores signed integers. A negative number is written by inverting every bit of its positive twin and adding 1, so -5 in 8 bits is 00000101 inverted (11111010) plus 1, which is 11111011. The sign bit is the leftmost bit, and the same adder works for signed and unsigned numbers. An N-bit two’s complement number ranges from -2^(N-1) to 2^(N-1) - 1, so 8 bits give -128 to 127.

    Why is 11111111 sometimes 255 and sometimes -1?

    A bit pattern has no meaning until you choose a representation. As an unsigned 8-bit number 11111111 is 255. As 8-bit two’s complement it is -1, as one’s complement it is -0, and as sign-magnitude it is -127. This page always shows the representation you selected, and the same bits in the others.

    What is the difference between one’s complement, two’s complement and sign-magnitude?

    Sign-magnitude uses the leftmost bit as a sign and the other bits as the size, so -5 is 10000101. One’s complement negates by inverting every bit, so -5 is 11111010. Two’s complement inverts and adds 1, so -5 is 11111011. The first two have two zeros (+0 and -0); two’s complement has one zero and one extra negative value.

    What is overflow and what is underflow?

    Overflow is a result larger than the largest value the width can hold (100 + 50 in 8-bit two’s complement is 150, above 127). Underflow is a result smaller than the smallest value (-100 - 50 is -150, below -128). For unsigned numbers, a subtraction that would go below 0 is an underflow. The true result is always shown.

    What happens when a result does not fit?

    You choose. “Report” stores nothing and shows the warning. “Wrap around” keeps only the bits that fit, so 150 becomes -106 in 8-bit two’s complement. “Saturate” stops at the nearest limit, 127 here. Wrapping is what a plain adder does; saturation is common in signal processing. Neither is the true result, and the page says so.

    How does the calculator detect two’s complement overflow?

    It adds the bit patterns and compares the carry into the sign bit with the carry out of it. If they differ, the result overflowed. The engine also checks that against exact integer arithmetic, and refuses to show a result if the two disagree.

    Why does negating -128 give -128?

    In 8-bit two’s complement the range is -128 to 127, so +128 does not exist. Inverting 10000000 gives 01111111, and adding 1 gives 10000000 again. The calculator reports this as an overflow.

    How do I sign-extend a number to more bits?

    Copy the sign bit into the new bits on the left: -5 is 11111011 in 8 bits and 1111111111111011 in 16 bits. Filling with zeros instead gives 251, which is wrong for a negative number. Sign-magnitude moves the sign bit instead, and unsigned numbers are filled with zeros. Narrowing is only allowed when the value still fits.

    What happens if I type a short bit pattern?

    It is padded with zeros on the left to the chosen width, so 101 at 8 bits is 00000101, which is +5, not -3. Short patterns are never sign-extended automatically, because the width is part of the question.
